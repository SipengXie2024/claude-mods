# 带原文索引的上下文交接

范围：Claude Code mods 的上下文连续性设计，实现位于 `mods/context-memory`。运行验证记录见 `context-memory-verification.md`。

## 目标

在长任务发生上下文压缩后，模型仍然知道用户当前要求、未完成工作和已有证据；细节离开活动上下文后，可以通过稳定引用读取原始记录。压缩不因插件增加额外的模型请求。

机制保留可查询证据及其来源。它不承诺模型永远正确理解要求，也不承诺压缩无损或降低总成本。

## 三种记录

### 原始记录

保存用户消息、助手回复、工具调用及可取得的结果，并标注会话、agent、分支和来源。查询返回带来源的文字，不将旧工具协议块重放进活动对话。

项目转录文件是原始记录的来源。存储采用本地 SQLite，工具通过随 mod 分发的本地辅助程序访问；完整历史不放进总容量上限 4 MiB 的 `$.store`。缺失原文、已截断输出必须保留缺失标记，不能用摘要冒充原文。

转录索引参照 Agentix 宿主的会话流游标：每份转录记录已读位置、该位置之前 4096 字节的 SHA-256 和活动链末端。同步时校验哈希，只解析游标之后的完整行，新行、父链接和游标在同一事务中写入；活动链只在末端变化时追加，回退到其他分支或父链接改变时重算。文件变短或游标之前被改写时从头重建。对话行一经写入不再改写。每行文字只存一份；去掉历史查询内容后可搜索文字不同的行，才另存一份搜索用文字。快照条目同样只存阅读文字和必要时的搜索文字，不保存原始消息 JSON。

数据随 Claude Code 的转录过期：同步时删除文件已不存在的转录索引；快照记录拍摄时会话主转录的路径，文件消失后删除快照和交接消息，因为已经没有对话能恢复它；仍被现存转录的交接标记引用的快照及其上级保留。判断依据是快照自己记录的文件，不推测转录所在目录。交接标记指向归档中不存在的检查点时视为没有可搜索内容，不阻止压缩。

### 任务笔记

正在工作的模型用 `notes_write` 维护一份简短笔记：目标、用户原话中的约束、已完成内容及证据位置、未完成事项和下一步。每次调用替换整份笔记，上限 12000 个字符，不能包含 `[context-memory` 标记。插件在系统提示末尾加一段说明，告诉模型在任务有实质变化时更新笔记。

笔记以对话记录为准：最新笔记是当前上下文中最后一次成功的 `notes_write`，或上一次压缩交接消息里带的笔记，以较晚者为准。回退对话、恢复会话和 fork 因而自动使用当前分支上的笔记，数据库里不另存可能属于已放弃分支的版本。

笔记记录模型自己的理解，推断不构成用户授权；压缩投影中的 user 角色也可能表示摘要或注入信息。

### 交接消息

压缩安装时追加的一条纯文本 user 消息。它必须作为对话消息存在：模型读它，恢复和回退沿对话链找到它，历史查询的范围以它的标记为根。`SessionCompacted.messages` 没有隐藏消息的字段，所以界面显示由 `ui.render` 的 `UserMessage` 钩子处理：折叠状态显示一行（检查点、存档条数、笔记字数，条数取自标记属性 `[context-memory checkpoint=<id> items=<n>]`，不解析正文措辞），ctrl+o 显示全文，模型输入不变。消息包含：检查点编号与此前检查点、本次压缩输入条数、最新笔记原文（或说明压缩前没有笔记）、原文查询方法、更新笔记的方法，以及历史状态需要核实的提醒。交接消息是截至压缩位置的资料，之后的用户消息和执行结果继续更新任务。

## 一次压缩的完整过程

1. **取得实际输入。** 在 auto/manual/plugin `session.compact` 事件中，取得该 loop 的冻结消息集合 `e.messages`，并从中找出最新笔记。
2. **原生压缩。** 把笔记附在原生压缩指令之后，用户在 `/compact` 后输入的文字保持在最前。最近 10 条之前、1024 个字符以上的 `Read`、`Grep`、`Glob` 输出在交给摘要的消息里换成指向归档的说明（参照 Agentix 压缩前的不调模型剪裁）：改写的消息失去引擎句柄、由文字和工具块重建，工具编号和配对不变，有副作用的工具输出不动。然后调用 `next(e)`。保留引擎返回的消息集合、顺序、内容和句柄。压缩失败或被取消时插件不写入任何内容。
3. **保存快照。** 原生压缩成功后，插件生成 checkpointId，记下会话主转录的路径，每个条目使用 `(sessionId, agentId, checkpointId, itemIndex)` 作为持久化引用。`handle` 仅供本次引擎调用使用。快照的父检查点取自压缩输入中携带的交接标记，不读取转录索引，所以这一步只与本次输入大小有关。快照和交接消息文本在同一个事务里提交；提交失败时返回 skip，这次压缩作废，对话保持原样；提示写明原因和暂时停用插件的命令，避免写库持续失败时压缩一直不可用而用户不知道出路。
4. **一起安装。** 在返回集合末尾增加交接消息，`toolUses` 为空，没有旧消息 id 或旧协议块。引擎按 `SessionCompacted` 返回合同一并安装。
5. **继续任务。** 模型在新上下文看到原生摘要、引擎保留的近期消息和交接消息；精确细节通过历史查询取得。

插件在整个过程中不发起模型请求。`precompute` 触发同样附上笔记后交给 Claude Code，交接消息只在真正安装压缩时生成。

## 历史查询

提供查找、按引用读取和列出会话三种能力，均支持分页和输出预算。每条结果显示来源、归属和原文范围。历史查询工具自身的调用和结果、交接消息不进入搜索候选，避免摘录副本被当作新证据。

- 默认范围：当前 agent 的活动转录和当前分支继承的快照。子代理另加所在会话主对话的转录，fork 子代理因而能读父会话原文，不需要在创建 fork 时另存快照。当前 agent 自己的转录已建索引时，它自己拍的快照不进搜索候选，因为活动链已经穿过压缩分界包含同样的消息；快照引用仍可读取。
- 项目范围：同一项目目录下其他会话的主转录，按文件修改时间从新到旧；可限定一个会话。其他会话的原文只证明当时说过什么，不构成当前要求。
- 匹配：空格分开的每个词都必须出现，字面匹配，ASCII 字母不分大小写。同义词、跨语言表述（“超时”与 “timeout”）由模型换词重查；插件不做语义检索，因为那需要嵌入模型和额外请求，与“插件不发起模型请求”的目标冲突。

hooks 模块在会话生命周期内保持加载时的版本，存储程序每次调用重新启动；每个请求带协议版本号，不一致时拒绝并提示 `/reload-plugins`。

## 恢复、分支与失败

- 数据库中的快照只有被当前活动历史里的交接消息引用，才属于当前分支。不能只读取数据库的“最新一份”。
- 快照只在原生压缩成功后保存；之后的安装若被引擎放弃，记录不被引用，恢复时不自动注入。
- 回退或分叉沿活动链及明确继承关系恢复；放弃分支上的笔记和授权不继承。
- 已执行的文件修改、远端操作和后台进程不会随着对话回退自动撤销；需要执行新动作时核实实际状态。
- 归档写入失败时返回 skip，本次压缩作废，提示原因和暂时停用插件的命令；原生压缩失败时显示 Claude Code 给出的原因。

## 与现有 mods 的关系

新模块独立承载原文索引、任务笔记和压缩交接。Jev 的约 120 词 recap 继续服务任务分类，保留现有调用时机、模型和分类行为。

当前 `$.session.compact()` 不允许在运行中的 turn 主动调用。本方案接入引擎已有自动压缩与 `/compact`；不增加模型工具内直接执行 `new_context` 的入口。

## 接口依据与验收

当前 API 类型文件：`/tmp/claude-1000/bundled-skills/2.1.319/d750a89a3652619196558ff6582348c3/plugin-authoring/types/claude-code.d.ts`。

- 11663–11672：压缩返回值定义最终消息集合；有 handle 保留引擎原件，无 handle 的消息由 role/text/tool blocks 建立。
- 11702–11763：压缩输入、agentId、冻结消息、trigger 及可改写的 instructions。
- 8818–8915：`prompt.compose` 的系统提示分段。
- 11473–11599：追加事件身份、来源与实际保存结果。
- 2991–3002：主动压缩限制。

真实会话验收要求：

1. 压缩期间插件发起的模型请求为 0。
2. 每次压缩后的首次模型请求带有交接消息，其中笔记与压缩前最新的成功笔记一致；连续压缩时笔记从上一份交接消息继续传递。
3. 被拒绝的笔记不会成为最新笔记。
4. 关闭并恢复后能用历史查询读回压缩前的原文；fork 子代理能查询父会话原文。
5. 工具调用 ID 不重复，工具调用和结果配对有效。
