# claude-mods

Personal Claude Code mods (function-hook plugins), one plugin per folder under `mods/`.

| Mod | What it does |
|---|---|
| `subagent-opus` | Under a Fable or Mythos main loop, Agent-tool subagents start on Opus (forks and workflow agents untouched). |
| `no-bg-poll` | Denies `sleep N && <reader>` polling; background tasks notify on completion. |
| `workflow-opus-guard` | Under a Fable or Mythos main loop, denies a Workflow script unless every `agent()` call pins `model: 'opus'`. |
| `mode` | `/mode academic\|general` writes the repo's `.claude/settings.local.json` (restart to apply); paper repos get a one-time hint; status line shows academic mode. Both modes reply in the Plain output style; academic mode adds `prompts/academic.md` (academic judgment, submission register, review and rebuttal rules, the `~/.agents/writing/LESSONS.md` reminder) to the system prompt. |
| `jev` | Sets each Opus or Mythos prompt's effort with Jev (policy.v12). The start level is decided once per prompt from the task kind, read from a table per model (Opus 5.5, default medium; Mythos 5.1 and earlier Opus, default high), each kind with a start and a deeper start for work that needs something worked out (sources and per-level benchmark numbers in `~/.config/jev-opus/eval/effort-sources.md`). The tables start low and raise on failure where a failure shows itself (Opus 5.5: code, operations and visual work low; explanations, prose and research a step higher, since nothing would raise them), and a level a task was raised to holds while Jev reads the next message as carrying on the same task (`followup.v5` asks it beside the fault question); a prompt whose kind Jev is unsure of starts at high. Then, one level above the previous prompt's highest when the prompt says the last turn went wrong (max only after the top level was faulted twice), never below the previous level for a short acknowledgement (`继续`, `ok`), and, with probability `JEV_OPUS_EXPLORE` (default 0.10), one level up or down inside medium..max for exploration on a person's own prompt. Jev reads the prompt with what came before it: the end of the agent's last reply, a line of what the last turn did (tool calls, edited files, failed commands, a check still failing after a change; never the level it ran at), and a rolling recap that a small model (`JEV_RECAP_MODEL`, default `haiku`) rewrites in the background after each main-loop turn from the previous recap and that turn in full (goal, current task, the agent's last proposal word for word, standing instructions); so 我觉得可以. after the agent offered to write code reads as code, and an approval takes the kind of the work it approves. The recap request leads with Claude Code's identity sentence, without which `$.model.complete` comes back HTTP 429 on a subscription when `CLAUDE_CODE_ATTRIBUTION_HEADER=0`. Prompt rows record the `context` source; each update is a `recap` row (ok, time, sizes, the API error when it failed, the previous recap kept). After that only the ladder moves effort, and only up: a check (a Bash command running cargo test/build/clippy/check, pytest, go test/build/vet, tsc, eslint, ruff, mypy, or npm/pnpm/yarn/bun `test` or `run` of a script named test, build, lint, check, typecheck, verify or ci; also inside `ssh` and `docker exec`) that fails again, judged by its exit code alone, after the model changed code raises one level. A code change is a successful Edit, Write, MultiEdit or NotebookEdit, or a Bash command that edits files in place: `sed -i`, `perl -i`, an output redirection or `tee` into a file (a heredoc included), `patch`, `git apply` / `git am`, `git checkout … -- <path>`, `git restore`, or `cp` / `mv` / `install` into the work tree, also behind `sh -c`, `ssh`, `docker exec`, `xargs` and `find -exec`. After exit 0 it counts when a local file it names was modified during the call or is gone after it, and without a look for a remote edit, a patch, `mv`, `cp -p`, or a path with a variable or glob. After a non-zero exit only an edit chained by `&&` into a check counts (`sed -i … && npm test`, where the failure may be the edit's or the check's), and only when every file it names is local and was modified during the call. Such a command is the same check as the check alone, so `npm test` failing and then `sed -i … && npm test` failing is a repeat. What a check writes, and files written from inside an interpreter (`python - <<EOF`, `node -e`), are no code change. On Mythos the raise comes at the next request, at most twice per prompt; on Opus, whose effort change would not act before the next user turn, nothing changes mid-loop and a check still failing at the turn's end starts the next prompt one level up when that prompt continues the work (an acknowledgement, a fault, or a short prompt after an interrupted turn). A piped run, `|| true`, a denied call, WebFetch, lookups and one-off scripts never count. A background task's report continues the last prompt; a slash command is a new task judged from its expanded text; a Telegram message is a person's prompt. A `/effort` the person runs holds for the session until another `/effort` or a prompt with `[effort auto]`; `/model` is no `/effort`. Other session models (Fable, Haiku) are left alone, prompt included. The band above the prompt names the model of the loop whose transcript is in view, the main conversation or a subagent opened from the tasks list, and its effort trail (`Mythos 5.1 · ◆ Jev · high → XHIGH · check failed again`; the model alone, `Fable 5.1`, for a loop Jev leaves alone; `· local routing` without Jev, `· /effort` under a pin, `· done` once a subagent has ended); `/model` renames the main line at once. A prompt may carry its own range, `[effort xhigh..max]`, `[effort >=xhigh]` or `[effort max]`: that prompt's start and raises stay inside it, and the next prompt returns to the configured range (`/effort` pins still win); a subagent started under that prompt inherits the range unless its brief carries a tag of its own, whatever model the main loop runs; the journal records it as `promptBounds` (`promptBoundsInherited` on a subagent). Reads `~/.config/jev-opus/.env` (`JEV_OPUS_CONFIG_DIR` overrides the folder); journal rows (`prompt`, `step`, `check`, `outcome` with tokens, wait, checks and raises per turn) are appended to `mod-journal-YYYY-MM-DD.jsonl` (UTC) there. Jev is only called at loopback, `172.21.0.1` or a `JEV_ALLOWED_HOSTS` host, within `JEV_DEADLINE_MS` (default 6000); otherwise heuristics only. `JEV_FALLBACK_BASE_URL` / `JEV_FALLBACK_API_KEY` / `JEV_FALLBACK_MODEL` / `JEV_FALLBACK_DEADLINE_MS` / `JEV_FALLBACK_FORMAT` name a second endpoint asked only when the primary fails (deadline, HTTP error, no valid answers, circuit open); its answer sets the task kind only, never a raise; the journal records `jevProvider` and, after a fallback, `jevFallbackFrom`. `JEV_FORMAT` / `JEV_FALLBACK_FORMAT` set to `openai-decisions` make that endpoint speak OpenAI's Decisions API (`POST /v1/decisions`: noul as a predicate, a choice's options in the question set's order); any other value, System One. |
| `reply-language` | Attaches one line naming the reply language from the `language` setting (`chinese` → `用中文回复用户。代码、命令、标识符和提交信息保持原样。`; any other value → `Reply to the user in <language>. …`) beside every prompt: a person's own, a Telegram message, a background task's notification, a slash command. The system prompt's language rule sits at the far end of a long session, and English right before a reply (task notifications, compaction summaries, subagent reports) pulls the reply into English; the line sits next to the reply. No `language` setting, no line. |
| `tg-progress` | In a session started from Telegram (`--channels plugin:telegram@…`), a turn that runs 30 s gets one progress card in that chat: elapsed time, tool count, the current tool (Bash description or file name, never the command; every line redacted), edited after tool events at most every 10 s, ending as one line (done / interrupted / error). Not in the marketplace: load it only in that session with `--plugin-dir` (see `examples/claude-telegram`). Bot token from `$TELEGRAM_STATE_DIR/.env`; sends and edits only, never `getUpdates`. |
| `html-plan` | The community `html-plan` skill (anthropics/claude-plugins-community, html-plan 1.0.0) with Chinese prose: `pack.mjs` reads `。？！` as sentence ends and counts two CJK characters as one word, and under `<html lang="zh">` the page buttons, badges and the copied response are Chinese. Upstream changes: re-copy `skills/` and re-run the edits listed in `mods/html-plan/CHANGES.md`. |
| `math-render` | Draws the TeX math in assistant replies as Unicode in the terminal; the stored message and what the model reads keep the TeX. Inline math (`$…$`, `\(…\)`) becomes one line (`∑ᵢ₌₁ⁿ xᵢ²`, `(a + b)/2`, a script with no Unicode form written `x^q`); display math (`$$…$$`, `\[…\]`, a bare `equation`/`align` environment) on its own line becomes a fenced block of character art: stacked fractions, limits above and below, integrals and brackets stretched to their content, matrices, `cases`, `aligned`. Code spans, fenced code, prices (`$5 or $10`) and a display block still streaming stay as written; display art wider than the reply, or inside a table row, is written on one line. Characters only: the terminal draws no formula images here. |

## Install (this machine)

```
claude plugin marketplace add ~/sipeng/claude-mods
claude plugin install <mod>@sipeng-mods --scope user
```

The marketplace is a local folder, so sessions read each mod straight from `mods/<mod>`:
edit, then `/reload-plugins`.

## Check

```
claude plugin validate mods/<mod>
claude plugin test mods/<mod>
```

Jev's start levels are scored offline against the journal: `extract` joins each prompt row with its text from the session transcripts, `sheet` adds unlabeled prompts to the label file, `score` replays the current policy against the labels (person and `claude-draft` labels reported apart) and tabulates outcomes by start level. Items and labels hold your own prompts and stay in `~/.config/jev-opus/eval/`.

```
bun mods/jev/eval/jev-eval.ts extract
bun mods/jev/eval/jev-eval.ts sheet
bun mods/jev/eval/jev-eval.ts score
```

Labels are reviewed in the browser at `https://cc.bbd.sh/label/` (same login as `/plan/`): `mods/jev/eval/review-server.ts` runs as the user service `jev-label` on `127.0.0.1:7241`, shows each prompt without Jev's own decision, and saves a confirmed row as the reviewer's label (`JEV_REVIEWER`, default `sipeng`).
